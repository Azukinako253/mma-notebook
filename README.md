個人的な MMA（総合格闘技）トレーニングノートをまとめた Web アプリです。
打撃・組み・寝技の3カテゴリをタブで切り替えながら、技術セクション・写真・自由メモを記録できます。

Express + better-sqlite3 によるバックエンドを持ち、内容はすべて SQLite データベースに保存されます。ページを再読み込みしても、サーバーを再起動しても消えません。

## 特徴

- **タブ切り替え**：打撃 / 組み / 寝技の3タブで内容を整理
- **セクションの追加・編集・削除**：各タブの内容（ファイトスタイル、コンビネーション、使える技一覧、よくあるミス…）は固定ではなく、画面上から自由に追加・編集・削除できます
  - セクションの種類は4パターン：**カード**（見出し＋箇条書き）／**コンビネーション**（番号付きリスト＋タグ）／**警告・注意ブロック**／**技一覧テーブル**
  - 各セクションの中の項目（カード1枚、コンボ1個など）も個別に追加・編集・削除可能
- **画像アップロード**：各タブに写真参照エリアがあり、アップロードした画像はDBに保存されます（アップロード・削除どちらもサーバーに反映）
- **フリーノート**：タブごとの自由記述メモ。入力すると自動保存されます
- 現状は自分専用（ログイン機能などのマルチユーザー対応は未実装）のローカルアプリです

## ディレクトリ構成

```
mma-note/

│   ├── index.html         # mma-notebook.html へ即リダイレクトする入口

│   ├── style.css          # スタイル（CSS変数でテーマカラーを管理）
│   └── script.js          # タブ切り替え・セクションCRUD・画像/メモのAPI連携ロジック

├── db.js                    # better-sqlite3のDB接続・スキーマ定義・初期データ投入

├── tests/
│   └── smoke.test.mjs      # ビルド成果物の簡易チェック
├── package.json
└── .gitignore
```

## データ構造（DB設計）

- `notes`：タブごとの自由メモ（`key`=タブ名）
- `images`：アップロードされた画像（バイナリごとDBに保存）
- `blocks`：各タブのセクション（例：「コンビネーション」「使える技一覧」）
- `items`：セクション内の1項目（カード1枚、コンボ1個、警告1個、技一覧の1行）

`blocks`/`items`は「カード・コンビネーション・警告・技一覧テーブル」の4種類共通の汎用テーブルになっており、新しいセクションを追加したいときはアプリの画面から「＋ 新しいセクションを追加」するだけで済みます。

## セットアップ・使い方

Node.js 18 以上が必要です。

```bash
npm install
```

### サーバーを起動

```bash
npm run dev
```

`http://localhost:5173` でアプリが立ち上がります（APIサーバーが `public/` の静的ファイルも配信します）。初回起動時に `data/mma-note.db` が自動生成され、元々あった内容が初期データとして投入されます。

環境変数 `PORT` でポート番号を変更できます（例：`PORT=3000 npm run dev`）。

### ビルド

```bash
npm run build
```

`public/` の内容を `dist/` にそのままコピーします（バンドラ等は使用していません）。ビルド成果物は静的ファイルのみなので、DBを使う機能（セクションの追加・保存・画像アップロードなど）を試すには `npm run dev` でサーバーごと起動してください。

### テスト

```bash
npm test
```

`mma-notebook.html` が正しく存在するか、ビルド後に `dist/index.html` が生成されているか等を確認するスモークテストです。

### ビルド＋テストをまとめて実行

```bash
npm run verify
```

## 今後の拡張について

現状は自分専用のローカルアプリですが、`blocks`/`items`の汎用設計により新しいセクション種別を増やしやすい構成にしてあります。将来的に複数ユーザーに対応する場合は、認証機能の追加と各テーブルへの `user_id` の追加が必要になります。

## Git運用ルール（複数端末・複数セッションで作業する場合）

このリポジトリは複数の端末・Claude Codeセッションから同時に触られることがあるため、`main`ブランチへの直接コミットが重なると「発散（divergent branches）」が起きやすいです。実際に一度、別々のセッションが同じ機能を別々に実装してpushし、大規模なコンフリクトになったことがあります。再発を防ぐため、以下を徹底してください。

1. **作業を始める前に必ず最新化する**
   ```bash
   git switch main
   git pull --ff-only origin main
   ```
   `--ff-only` を付けておくと、もし既に発散していた場合はここでエラーになって気づけます（気づかず作業を進めてしまうのを防げます）。

2. **`main`へ直接コミットせず、作業ごとにブランチを切る**
   ```bash
   git switch -c feature/画像アップロード改善
   ```
   ブランチ名は内容が分かるものにする（例：`feature/xxx`, `fix/xxx`）。

3. **作業が終わったらpushしてPull Requestを作る**
   ```bash
   git push -u origin feature/画像アップロード改善
   ```
   GitHub上でPRを作成し、`main`にマージする。直接pushではなくPR経由にすることで、他の変更との衝突に事前に気づける。

4. **複数の端末/セッションを並行して動かす場合は、事前にどちらが何を担当するか決めておく**
   同じファイル（`server.js`, `public/mma-notebook.html`, `public/script.js` など）を別々のセッションが同時に大きく書き換えると、自動マージがほぼ不可能なコンフリクトになります。同時に触る場合は範囲を分けるか、片方が終わってpullしてからもう片方が始めるようにする。

もし発散してしまった場合は、`git log --oneline main..origin/main` と `git log --oneline origin/main..main` で双方の差分を確認し、どちらを残すか（またはどう統合するか）を決めてから解決してください（`git reset --hard`は取り消せないので、対象ブランチをバックアップ用の別ブランチにpushしてから実行するのが安全です）。
